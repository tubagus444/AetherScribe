# L03 - Alur data melalui UI

Tanggal: 15 November 2026. Baseline aplikasi `020fb7c`.

Tambahkan delapan skenario di `e2e/dataUi.spec.ts`. Setiap test memakai context
Chromium baru dan dua proyek sintetis dengan bab/Codex, snapshot bab, timeline,
relasi serta marker Atlas. Setelah seed, semua aksi yang diuji dilakukan melalui
komponen aplikasi asli, bukan memanggil import/restore/delete service dari test.

## Cakupan

| Alur | Pemeriksaan |
|---|---|
| Ekspor/impor novel | Download lewat tombol ekspor, baca file unduhan, pilih ulang lewat tombol/input file, batalkan dialog lalu konfirmasi impor. Proyek lama tetap; naskah dan FK Codex/marker/timeline salinan di-remap |
| Ekspor/restore penuh | File hasil ekspor dipilih melalui UI, pembatalan mempertahankan data yang sudah berubah; konfirmasi mengembalikan data file, menyimpan snapshot pre-restore dan naskah dapat dibuka setelah reload |
| Penolakan file | JSON rusak, backup penuh pada jalur impor novel dan file proyek pada jalur restore penuh tidak membuka konfirmasi atau mengubah record; input direset |
| Gagal impor | Hook creating Dexie pada chapters melempar error setelah proyek baru mulai ditulis; UI menampilkan error, seluruh record asal tetap, proyek parsial tidak tersisa, file bisa dipilih ulang |
| Gagal restore | Hook yang sama menggagalkan insert sesudah proses restore mulai menulis; transaksi memulihkan record asal, UI menampilkan error dan pemilihan file tetap dapat dipakai |
| Hapus bab | Klik pertama tidak menghapus, reload membatalkan niat hapus; konfirmasi dua klik menghapus bab/snapshot dan melepas chapterId timeline sambil mempertahankan narasi dan proyek lain |
| Hapus Codex | Batal tidak mengubah data; konfirmasi menghapus relasi dan melepas referensi marker/timeline tanpa menghapus naskah atau Codex proyek lain |
| Hapus proyek | Batal mempertahankan seluruh record; konfirmasi menghapus proyek aktif dan turunannya serta mempertahankan bab/Codex proyek lain |

File dipilih dengan Playwright filechooser.setFiles pada input produksi; ini
menguji File API, parsing/validasi dan dialog aplikasi, bukan mengotomasi dialog
file sistem operasi secara manual. Ekspor menggunakan Blob/download browser asli.
Satu mutasi DB terkontrol pada skenario restore menyiapkan kondisi data berubah;
restore sendiri tetap dijalankan lewat tombol dan dialog.

Injeksi kegagalan memakai hook Dexie asli, bukan mock fungsi service; karenanya
rollback transaksi native IndexedDB dan penanganan error UI ikut diuji. Hook
dilepas sesudah assertion dan context dibuang setiap test. Tabel operasional
utama dibandingkan sebelum/sesudah, dengan timestamp lastOpened/lastModified
yang memang dapat berubah tidak dipakai sebagai ukuran kerusakan. Snapshot
pengaman dapat tetap tersimpan saat restore gagal; itu bukan data parsial restore.

## Isolasi dan hasil

Request luar origin diblokir, mode AI local-only diaktifkan, daftar model Ollama
dimock kosong agar pembukaan Pengaturan tidak mengakses server model. Tidak
menggunakan naskah pengguna, provider/Drive nyata, token akun atau profil browser
persisten. Fixture tidak masuk bundle production. CI menemukan spec baru melalui
test:e2e yang sudah ada; tidak membutuhkan perubahan workflow.

Typecheck umum/strict/maintenance, 90 berkas/787 tes dan 29 tes Chromium lulus
lokal. Tidak ditemukan bug produksi baru dalam cakupan yang diuji; kegagalan
awal tes berasal dari locator yang tidak spesifik dan asumsi panel setelah reload,
yang diperbaiki pada test. Tidak mengubah kode aplikasi atau skema/dependensi.
Build/production smoke dan coverage tidak dijalankan ulang karena perubahan
hanya pada tes/dokumentasi. Hasil CI GitHub terbaru tetap terikat SHA pada L01,
bukan klaim bahwa runner sudah menjalankan L03.

L03 selesai untuk alur di atas. Belum mencakup file picker OS manual, semua variasi
file legacy/gzip/ukuran besar/aset Atlas melalui UI, kegagalan quota browser,
OAuth/Drive, atau error penghapusan melalui UI. Unit domain deletion/backup yang
lebih luas tetap menjadi pengaman pelengkap; penambahan alur berikutnya perlu tes
sesuai risikonya.
