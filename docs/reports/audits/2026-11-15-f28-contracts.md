# F28.2 - Kontrak data pada batas modul

Tanggal: 15 November 2026. Kelanjutan dari [inventaris F28.1](2026-11-15-f28-inventory.md)
pada baseline `dec2940`. Snapshot inventaris tetap menyimpan kondisi sebelum
perubahan ini; status tahap aktif ada di [ROADMAP](../../../ROADMAP.md).

## Kontrak dan pemakaian

| Batas | Sumber kontrak | Perilaku |
|---|---|---|
| Metadata daftar dan bab lengkap | `chapterMetadata.ts`, `chapterContracts.ts` | Metadata daftar memiliki ID wajib dan tidak memiliki content. Input pembuatan menolak ID/listMetadata milik entitas lama; duplikasi membuang keduanya sebelum Dexie menghasilkan ID dan metadata baru. Pengiriman bab tersimpan ke worker memeriksa identitasnya. |
| Context worker | `contextProtocol.ts` | Dua belas task memiliki pasangan payload/result; CANCEL dan INDEX_MANUSCRIPT memiliki envelope tersendiri. Sender mengembalikan tipe hasil sesuai task. Receiver memeriksa input sebelum komputasi, dan hasil diperiksa sebelum dikirim serta sebelum Promise diselesaikan. |
| Orama worker | `rag/oramaProtocol.ts` | INIT, index/update/remove dan dua bentuk search dibedakan. Search memakai ID request; hasil biasa berbeda dari hasil dengan skor. Pesan mutasi gagal membawa payload dan retry yang diperiksa sebelum dikirim ulang. Antrean dan batas satu retry tetap dipakai. |
| Respons AI | `ai/responseContracts.ts`, `ai/providerTypes.ts` | JSON HTTP/SSE masuk sebagai unknown. Teks harus string, usage yang dikenal harus angka finite nonnegatif; nol tetap valid. Nama provider diperiksa sebelum dispatch. Error provider diambil hanya dari field string yang dikenal. |
| JSON domain dari model | `ai/resilience.ts`, `ai/index.ts` | parseJsonArray mengembalikan unknown[]. Sanitasi finding/audit/enrichment memeriksa record dan field sebelum dipakai. Callback onRetry menerima error unknown. |

Facade publik `contextEngine`, `oramaSync` dan layanan AI tetap tersedia dengan
nama yang sama; SceneSearchHit diekspor ulang dari kontrak bersama. Komputasi
berat tetap di worker, model transformers tetap lazy. Kontrak ini tidak mengubah
versi database v34 atau dependensi.

## Penolakan data dan batas validasi

- Pesan context/Orama yang salah dengan ID numerik mendapat balasan error;
  pesan tanpa identitas yang dapat dibalas diabaikan sebelum pekerjaan dijalankan.
- Hasil worker yang salah menolak Promise dan membersihkan timer. Progress
  context yang salah mengakhiri worker dan menolak request tertunda, sehingga
  data invalid tidak memperpanjang heartbeat. Orama menolak request tertunda
  saat menerima respons invalid; antrean worker tetap bisa menerima pesan valid.
- Map pada PresenceIndex dan Set pada excludeWords memakai structured clone,
  bukan serialisasi JSON. Angka skor nol dan usage nol dipertahankan.
- Objek sebagai completion atau potongan teks SSE ditolak. Bentuk field opsional
  provider yang tidak hadir tetap mengikuti perilaku lama; kontrak tidak mewajibkan
  semua field milik API provider. Reader SSE tetap dibatalkan/dilepas pada error.
- Guard Codex memeriksa field inti yang dipakai transport, bukan seluruh struktur
  opsional domain. Ini bukan pengganti validasi backup/import, FK, checksum,
  kebijakan provider, atau pemeriksaan kredensial.

## Pengaman dan bukti

`src/contracts/f28Contracts.typecheck.ts` ikut `tsc --noEmit`: proyeksi daftar
ditolak sebagai bab lengkap, input pembuatan menolak entitas dengan identitas,
payload salah ditolak, pasangan task/result lengkap, hasil token berupa number,
dan callback error berupa unknown. Pengaman negatif memakai assertion tipe tanpa
ts-ignore/ts-expect-error; belum mengaktifkan strict global.

Tes runtime mencakup matriks input/output semua task context, hasil report dari
builder asli dengan bab berisi teks, Map/Set, progress/result invalid, cleanup
timer, input worker invalid sebelum tokenizer/model, pesan Orama dan antrean
sesudah penolakan, completion/SSE/usage invalid serta duplikasi bab.

Dua probe terhadap source baseline `dec2940` gagal sesuai ekspektasi:

1. Proxy lama menyelesaikan Promise dengan objek completion, padahal output harus
   teks. Source baru menolak objek tersebut.
2. Context worker lama memproses COUNT_TOKENS dengan text berupa angka; source
   baru menolak sebelum tokenizer/model dipanggil.

Source dipulihkan setelah setiap probe. Seluruh data tes sintetis, tanpa key,
provider, model unduhan atau profil pengguna nyata. Verifikasi akhir: typecheck,
87 berkas/782 tes, build, 16 tes Chromium, dan smoke startup/offline lulus lokal.
Peringatan build lama tentang chunk besar, eval ONNX dan Browserslist masih ada.

## Handoff

F28.2 selesai; F28 induk tetap terbuka. F28.3 berikutnya menetapkan cakupan strict
bertahap beserta check CI. Any/catch/cast pada pembentukan request provider dan
internal layanan lama belum semuanya dirapikan. Ekstraksi facade AI dan Atlas,
tes interaksi Atlas yang kurang, serta audit ulang dependency/ekspor tetap berada
di F28.4-F28.6.
