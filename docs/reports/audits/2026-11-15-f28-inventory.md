# Inventaris awal F28.1 — kode, kontrak, dan pengaman

Tanggal: 15 November 2026. Source dasar: `dec2940`. Laporan ini hanya inventaris;
tidak mengubah perilaku, schema v34, konfigurasi TypeScript, atau dependency.
Rencana F28 yang sudah ada di working tree dipertahankan. Status pekerjaan aktif
tetap di [ROADMAP](../../../ROADMAP.md). Data terstruktur: [snapshot AST](2026-11-15-f28-inventory.json).

## Metode dan batas

```powershell
node scripts/inventory-f28.mjs --output=test-results/f28-inventory.json
```

Direktori output harus sudah tersedia. Script membaca file TS/TSX yang terlacak
Git di src serta server*.ts pada root; menghitung node TypeScript AST dan komentar
directive, lalu menyelesaikan import literal memakai konfigurasi proyek. Snapshot
berisi hitungan per file serta ekspor/import/konsumen untuk 19 modul fokus.

`any` adalah tipe eksplisit, bukan kata dalam komentar atau jumlah implicit-any.
Assertion mencakup `as const` yang sah; non-null assertion tidak otomatis bug.
Baris dihitung sesudah whitespace akhir dibuang. Konsumen berarti file dengan
import/re-export sintaktis, termasuk tipe dan tes, bukan jumlah pemanggilan.
Dynamic import literal dicatat; `new URL(..., import.meta.url)` worker, import type
expression dan referensi dinamis nonliteral perlu review manual. Karena itu
hasil ini **bukan bukti dead code/dependency tidak dipakai**. Tidak ada dependency
yang direkomendasikan dihapus berdasarkan hitungan ini saja.

## Kontrak dan ketergantungan yang harus dijaga

1. **DB dan domain.** Chapter lengkap berisi HTML; ChapterListMetadata adalah
   proyeksi tanpa content. readChapterList/readLatestChapterModified dan hook
   metadata v34 sudah menjadi fondasi, bukan perlu dibuat ulang. Mutasi/duplikasi
   melalui chapterOperations; penghapusan melalui entityDeletion. Backup/import
   mempunyai validator scope/checksum/FK dan snapshot pengaman. Jangan melewati
   service tersebut ketika merapikan tipe atau mengekstrak UI.
2. **Context worker.** contextEngine membangun Worker(contextWorker URL), memakai
   request ID, progress heartbeat dan pending timeout. contextProtocol sudah
   membedakan CANCEL dan indexing fire-and-forget, tetapi payload task masih any
   dan hasilnya belum dipetakan per task. F28.2 perlu peta input/output, progress
   dan error yang eksplisit; structured clone bukan JSON serialization.
3. **Orama.** oramaSync membuat oramaWorker melalui URL; worker memakai oramaStore.
   Pesan INIT/mutasi/search dan reply ID/error perlu kontrak bersama. Pertahankan
   antrean, generated key setelah commit, rollback dan project isolation.
4. **AI.** Konsumen fitur → facade index → konteks/settings/kebijakan → proxy/SSE
   → endpoint server. CredentialStore/providerPolicy/errorPrivacy/circuitBreaker/
   resilience sudah dipisah. Jangan menduplikasi atau memindahkan ulang fondasi
   ini. Respons provider/finding/usage perlu diperlakukan unknown pada boundary;
   type assertion tidak menggantikan pemeriksaan bentuk data.
5. **Atlas.** MainView lazy-load AtlasPanel; panel memakai useAtlas, upload gambar,
   navigation, presence index, analytics/hierarchy dan child canvas/sidebar.
   useAtlas sudah menangani CRUD dan deleteAtlasMap memakai cleanup domain F11.
   Rencana ekstraksi melanjutkan pemisahan state/filter/seleksi serta UI, bukan
   membuat jalur CRUD kedua. Jaga URL Blob, lifecycle Leaflet dan keamanan DOM.

## Handoff ke F28.2 dan F28.3

Urutan batch kecil yang disarankan:

1. contextProtocol + sender/receiver: tipe input/output tiap task dan tes kontrak;
   pertahankan cancellation, progress dan lazy loading. Lanjut Orama sesudah
   pola ini jelas, tanpa mengganti algoritme search atau membangun skema DB baru.
2. ai/types + normalisasi error/response pada proxy/SSE/parser: satukan provider,
   narrow unknown dan uji malformed data sebelum ekstraksi facade.
3. Audit DTO entitas/proyeksi/mutasi DB dengan memakai tipe metadata F23 dan
   service domain yang sudah ada. Perubahan public API harus dilacak ke seluruh
   konsumen pada snapshot; jangan menghilangkan validasi runtime demi tipe.
4. Coba strict check pada kontrak/helper dengan dependensi terbatas; catat semua
   import transitif yang ikut diperiksa. `include` config kecil tidak otomatis
   membatasi pemeriksaan hanya file tersebut. Jangan langsung strict seluruh app
   atau menyembunyikan error dengan any/ignore/non-null baru.

F28.1 tidak menambahkan guard test baru, menghapus dependency, mengaktifkan strict,
atau memecah panel. Gap di atas menjadi acceptance sebelum perubahan pada batch
terkait. F28.2–F28.6 dan item F28 induk tetap belum selesai.
