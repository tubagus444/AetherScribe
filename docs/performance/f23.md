# F23: metadata dan pembacaan berulang

Pengukuran 14 November 2026 di Windows/Chromium 159, Node 24.15.0, working tree
di atas `1c693f8`. Raw data: [f23.json](f23.json). Baseline query yang setara source
lama dan query baru dijalankan pada dataset IndexedDB v34 yang sama, sehingga
perbandingan tidak mencampurkan perbedaan isi novel atau cache antar-database.

Lima sample warm per operasi, localhost, halaman kosong terisolasi tanpa React
app/model/provider. Semua data sintetis. Angka berikut adalah median milidetik:

| Fixture | Daftar lama → baru | Timestamp terbaru lama → baru | Ranking adegan lama → baru |
|---|---:|---:|---:|
| 10 bab × 1.000 kata, 100 adegan | 1,2 → 0,8 | 0,7 → 0,3 | 4,4 → 5,0 |
| 100 bab × 2.000 kata, 1.000 adegan | 17,4 → 2,4 | 8,7 → 0,2 | 48,3 → 43,8 |
| 500 bab × 5.000 kata, 10.000 adegan | 193,3 → 7,0 | 79,5 → 0,4 | 416,0 → 427,0 |

Hasil daftar dan ranking diperiksa sama sebelum pengukuran. Ranking memakai
vektor 384 dimensi dan query sintetis identik, termasuk skor seri. Tidak memakai
inferensi model; waktu ini mencakup pembacaan DB/skoring/ranking, bukan embedding
query atau seluruh interaksi UI. Pengukuran lokal tidak menjamin angka yang sama
pada perangkat/runner lain. Ranking bukan selalu lebih cepat: batch read memiliki
overhead, sementara manfaat utamanya adalah batas memori.

## Memori yang diukur

CDP Runtime.getHeapUsage digunakan setelah GC, dengan baris yang dibaca ditahan
pada titik working set query. Ini bukan peak heap aplikasi atau heap React sesudah
query selesai. Baseline menahan hasil full-record yang memang hidup selama
sort/map; versi baru menahan proyeksi key metadata. Temporary split/stringify dan
memori internal IndexedDB tidak dijumlahkan.

| Bab | Delta JS heap, baris penuh | Delta JS heap, metadata | Backing storage metadata |
|---|---:|---:|---:|
| 10 | 64.072 byte | 832 byte | 97 byte |
| 100 | 1.017.964 byte | 6.556 byte | 997 byte |
| 500 | 12.591.564 byte | 32.164 byte | 5.397 byte |

## Desain dan tradeoff

- Schema v34 menambah covering index `[projectId+listMetadata]`, timestamp index
  `[projectId+lastModified]`, dan scene keyset index `[projectId+id]`. Tidak ada
  tabel/FK baru. Tuple listMetadata berisi order/title/status/count/modified; ID
  berasal dari primary key cursor, sehingga auto-generated ID tetap benar.
- Migrasi menelusuri bab lewat cursor dan menghitung metadata sekali per record.
  Creating/updating hooks memperbarui tuple dalam transaksi bab yang sama. Hanya
  perubahan content yang menghitung ulang kata; perubahan metadata memakai count
  sebelumnya. Nilai metadata pada file impor/restore tidak dipercaya.
- ChapterList, WritingStats, dan Dashboard membaca key metadata tanpa mengambil
  HTML; auto-index membaca satu key timestamp terakhir. Index menambah biaya
  disk/tulis dan migrasi sekali saat upgrade. Teks bab tetap sumber kebenaran.
- Query comparison menggunakan structural equality untuk data biasa, bukan
  menyalin seluruh hasil ke JSON string. Objek non-data seperti Map/Blob dianggap
  berubah secara konservatif; perubahan tidak disembunyikan sebagai `{}`.
- Semantik search tetap exact dot-product terhadap seluruh kandidat proyek.
  Keyset paging mengambil maksimum 256 vektor per batch dalam satu transaksi
  readonly; tidak ada cursor IPC per baris. Stable heap menyimpan maksimum top-k
  hit dan menjaga urutan seri sesuai primary key lama. Complexity ranking menjadi
  O(N log k), bukan full sort; pencarian exact tetap O(N × dimensi). Cancellation
  diperiksa pada batch/row checkpoint, tanpa await non-DB di tengah transaksi.

## Reproduksi dan batas

```powershell
npm ci
npx playwright install chromium --no-shell
npm run test:data-paths -- --output=test-results/data-paths.json
```

Script menjalankan server test port 4182, menggunakan native IndexedDB pada
context baru dan menutupnya sesudah selesai. Vite test HMR memakai 4178; jangan
jalankan bersamaan dengan `test:e2e`. Tidak perlu build production. CI menjalankan
benchmark setelah browser tests, tanpa ambang latency yang rentan noise; hasil
yang berbeda menggagalkan pemeriksaan, angka timing disimpan sebagai artefak.

Test terpisah mencakup upgrade v33 → v34 di fake-indexeddb dan Chromium, edit,
metadata-only update, rollback, project move, import/restore, delete, live-query
invalidation, generated ID, top-k/tie/project isolation dan cancellation. Browser
memeriksa statistik header/dashboard setelah editor flush. Guard tanpa JSON
serialization gagal pada hook baseline `1c693f8`, kemudian lulus setelah fix.

Belum mengukur upgrade multi-tab, quota exhaustion saat migrasi, Firefox/Safari,
semua bentuk record rusak, atau latensi inferensi model nyata. Penulisan lewat
native IndexedDB di luar API Dexie aplikasi melewati hook; fixture startup mentah
menyediakan tuple yang sesuai. Metadata tidak dipelihara oleh cache terpisah,
sehingga rollback/delete tidak meninggalkan cache yatim. Tidak semua full scan
di fitur lain dihapus; analisis yang membutuhkan isi naskah tetap membacanya.
