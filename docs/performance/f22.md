# F22: beban pemuatan awal

Pengukuran lokal 14 November 2026, Windows, Node 24.15.0, Chromium 159.0.8154.6.
Baseline berasal dari build commit `786cc5d`; sesudah perbaikan memakai working
tree F22 di atas commit tersebut. Raw sample: [sebelum](f22-before.json) dan
[sesudah](f22-after.json). Field commit pada kedua JSON menunjuk HEAD dasar yang
sama karena implementasi F22 belum di-commit ketika pengukuran dilakukan.

| Ukuran / median | Sebelum | Sesudah | Perubahan |
|---|---:|---:|---:|
| Entry JS, byte | 2.026.553 | 1.251.421 | -38,2% |
| Entry gzip, byte | 631.768 | 392.884 | -37,8% |
| File entry context worker, byte | 6.560.002 | 5.737.026 | -12,5% |
| JS resource halaman sampai editor terlihat, byte | 2.198.463 | 1.423.289 | -35,3% |
| Editor terlihat, ms | 474,0 | 408,0 | -13,9% |
| Main-thread ScriptDuration, ms | 220,2 | 173,5 | -21,2% |

Ini lima context browser baru per build, localhost tanpa throttling, viewport
default 1280x720, dan fixture IndexedDB sintetis yang sama: satu proyek/bab dengan
3.000 kata. Script membangun skema melalui aplikasi nyata pada context terpisah,
mengisi fixture, lalu menyalin storageState IndexedDB ke context baru per sample.
Tidak memakai profil/data/key pengguna. Timing dihitung sampai editor terlihat;
ScriptDuration berasal dari CDP dan byte JS dari Resource Timing halaman pada
titik itu. Metrik tersebut tidak menjumlah semua transfer/CPU worker atau kerja
latar yang baru dimulai sesudah editor terlihat.

Service worker diblokir hanya pada sample startup agar instalasi precache tidak
mengacaukan perbandingan. Angka timing bergantung perangkat/runner; hasil ini
bukan jaminan percepatan yang sama pada setiap perangkat atau jaringan. Tidak ada
ambang timing CI yang rentan noise. Ukuran bundle, assertions pemuatan runtime,
serta correctness offline diperiksa terpisah.

## Perubahan dan batas

ExportManager dimuat lewat React.lazy ketika dialog ekspor dibuka, sehingga
PDF/DOCX tidak ikut dievaluasi bersama editor. Registry ikon aksi dipisahkan dari
ActionsPanel agar menu seleksi tidak menarik seluruh panel; peringatan import
statis/dinamis ActionsPanel hilang.

Context worker mengimpor transformers pada getEmbedder, bukan saat worker boot.
Konfigurasi worker ES module mengizinkan chunk dinamis. Pengaturan model tetap
allowLocalModels=false dan numThreads=1, dengan promise bersama/retry yang sama.
Tokenizer masih statis, sehingga entry worker tetap besar. Ukuran entry worker
bukan total seluruh chunk yang akhirnya diperlukan fitur semantik.

Kebijakan precache tidak dikurangi: aset lazy tetap disimpan agar fitur yang belum
dibuka bisa digunakan offline. Precache sekitar 10,8 MiB tetap hampir sama
(89 menjadi 100 entri); ini optimasi jalur startup, bukan pengurangan besar ukuran
instalasi offline. Model embedding eksternal tetap memerlukan unduhan/cache model
seperti sebelumnya, dan tidak diunduh dalam benchmark.

## Reproduksi

```powershell
npm ci
npx playwright install chromium --no-shell
npm run build
npm run test:startup -- --output=test-results/startup.json
```

`test:startup` mengukur lima sample, kemudian memakai context baru dengan service
worker aktif. Sesudah precache aktif, koneksi dibuat offline: reload editor,
COUNT_TOKENS melalui worker produksi baru (hasil `Hello world` = 2), dan unduhan
Markdown melalui dialog ekspor lazy harus berhasil. Server terisolasi memakai
port 4181 dan ditutup sesudah pemeriksaan. Port terpakai menyebabkan kegagalan;
server pengguna tidak dipakai ulang. Build harus dibuat lebih dahulu.

CI menjalankan pemeriksaan ini sesudah build/smoke production, menyimpan JSON di
artefak test-results. Suite lain tetap menguji worker/cancel dan ekspor/backup.
Belum menguji model embedding nyata, seluruh format ekspor secara offline,
browser selain Chromium, atau perangkat lambat/jaringan WAN. Tidak mengubah
schema DB/dependency atau aturan offline aplikasi.
