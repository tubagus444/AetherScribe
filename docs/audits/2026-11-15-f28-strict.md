# F28.3 - Pemeriksaan TypeScript strict bertahap

Tanggal: 15 November 2026. Melanjutkan [kontrak F28.2](2026-11-15-f28-contracts.md)
pada baseline commit `264d592`. Status aktif ada di [ROADMAP](../../ROADMAP.md).

## Cara menjalankan dan batas konfigurasi

```powershell
npm run lint
npm run lint:strict
```

`lint` tetap memeriksa proyek dengan konfigurasi umum. `lint:strict` memakai
`tsconfig.strict.json`, mewarisi target/module/alias proyek dan mengaktifkan
`strict: true` serta `noEmit` yang diwarisi. Ini mencakup antara lain
strictNullChecks, noImplicitAny, strictFunctionTypes, strictPropertyInitialization,
dan useUnknownInCatchVariables. Konfigurasi umum belum strict seluruh aplikasi.

Workflow `critical-tests.yml` menjalankan kedua perintah sebagai step terpisah
di Windows/Ubuntu, sebelum tes dan build. Hasil runner GitHub belum diperiksa;
verifikasi pada tahap ini dilakukan lokal di Windows/Node 24.15.0.

`src/contracts/strict/strictSafety.typecheck.ts` memerlukan semantik strict:
null tidak boleh dianggap string, undefined tidak boleh dianggap number, dan
callback yang mewajibkan string tidak boleh menerima kontrak argumen opsional.
Assertion tipe sengaja gagal jika strict dimatikan. Folder ini dikecualikan dari
konfigurasi umum dan dimasukkan kembali oleh konfigurasi strict. File kontrak
F28.2 tetap diperiksa oleh kedua perintah. Keduanya tidak diimpor oleh aplikasi.

Angka ini mengecualikan declaration files/dependensi pihak ketiga. `include`
bukan batas yang mencegah import lain ikut diperiksa.

karena kode tersebut memengaruhi penanganan kegagalan/retry.

## Bukti bahwa pengaman bekerja

Probe sementara yang sama diperiksa dengan kedua konfigurasi:

| Kesalahan probe | Konfigurasi umum | Konfigurasi strict |
|---|---|---|
| Parameter tanpa tipe/konteks | Lolos | TS7006 |
| null diberikan ke string | Lolos | TS2322 |
| undefined diberikan ke number | Lolos | TS2322 |
| Membaca error.message dari catch tanpa narrowing | Lolos | TS18046 |

Probe dihapus melalui cleanup setelah pemeriksaan. Menjalankan konfigurasi strict
dengan override `--strict false` juga menghasilkan TS2344 pada ketiga assertion
strictSafety, sehingga pelemahan konfigurasi tidak sekadar membuat check hijau.
Perintah normal kemudian dijalankan kembali tanpa probe/override dan lulus.

Verifikasi akhir: `npm run lint`, `npm run lint:strict`, 87 berkas/782 tes, build,
dan diff-check lulus lokal. Peringatan build lama tentang chunk besar, eval ONNX
dan Browserslist tetap ada. Tes browser/production/offline tidak dijalankan ulang
pada tahap ini; tidak ada perubahan algoritme worker, skema DB atau dependensi.

## Pengecualian dan perluasan selanjutnya

- strict tidak melarang explicit any atau non-null assertion yang sudah ada.
  Dalam 26 berkas ini masih ada enam explicit any lama: dua di model domain
  `types.ts` dan empat pada payload Aho-Corasick. Ada 26 non-null assertion lama
  pada Aho-Corasick, kronologi, kontinuitas dan prosa. Ini utang yang tercatat,
  bukan error yang ditutupi dengan assertion baru untuk meloloskan tahap ini.
- `skipLibCheck: true` tetap diwarisi untuk declaration files dependensi; berkas
  implementasi proyek yang diimpor tetap diperiksa. Belum mengaktifkan
  noUncheckedIndexedAccess, exactOptionalPropertyTypes atau noUnusedLocals.
  Uji eksplorasi noUncheckedIndexedAccess menemukan asumsi indeks pada helper
  kalender/analitik/Aho-Corasick; perbaikannya perlu batch dan tes tersendiri.
- `ai/index.ts`, proxy client, context engine/worker, Orama transport/store,
  komponen React dan Atlas belum menjadi cakupan strict. Modul itu tetap ikut
  typecheck umum dan tes perilaku yang tersedia.
- Setelah ekstraksi AI/Atlas, perluas root bertahap dan audit ulang semua import
  transitif. Jangan menambah any, non-null assertion atau ignore untuk menutup
  diagnostik. Pemeriksaan aturan ini secara otomatis serta review akhir F28
  tetap pekerjaan F28.6.

F28.3 selesai untuk cakupan awal ini. F28 induk tetap terbuka; F28.4 berikutnya
memisahkan tanggung jawab layanan AI sambil mempertahankan facade publik.
